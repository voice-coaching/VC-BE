# 관리자 API별 조회·캐시 정책

작업 기준: BE main 74e8611 / FE main 50e2802. 관리자 화면 범위이며 일반 사용자 UI의 디자인·전역 조회 정책은 변경하지 않는다. 기존 HTTP/proxy no-store는 유지한다.

## 표시 및 삭제 계약

탈퇴(WITHDRAWN)/deleted_at 회원은 관리자 목록·합계·상세·기록·식별자 검색에서 제외한다. SUSPENDED는 관리 대상에 남긴다. 삭제 확인창에는 사유만 입력한다. 대상 번호는 URL, expectedUpdatedAt은 항상 새로 조회한 상세에서 자동 전달하며 최신 시각·본인 계정·권한·감사 검증은 유지한다. 관리자 DB 삭제의 범위와 외부 파일 제외 정책은 변경하지 않는다.

## 정책 선택

공유 HTTP/CDN/Next 서버 캐시와 서버 권한·개인정보 결과 캐시는 추가하지 않는다. 승인된 관리자 화면 안의 조회 데이터만 React Query 메모리 상태로 짧게 재사용한다. 로그인 세션 버전·경로·검색 조건을 키에 포함한다. localStorage/영구 저장에는 관리자 조회 결과를 보관하지 않는다.

staleTime은 이 시간 뒤에 화면이 자동으로 갱신된다는 뜻이 아니다. 재진입·창 포커스·직접 새로고침 시 조건에 따라 갱신한다. 회원 목록에 직접 새로고침 버튼을 제공하고 회원 상세 새로고침은 overview와 현재 records를 함께 갱신한다. 상시 polling은 추가하지 않는다.

## 무효화 및 권한

- 회원 변경: users 하위 및 작업 이력. 삭제 성공 시 해당 회원 상세/기록 캐시는 즉시 제거한다.
- 콘텐츠/음성 변경: contents 하위 및 작업 이력. 카테고리·회원 목록을 불필요하게 다시 불러오지 않는다.
- 공지, 문의, 알림 발송, 팝업 변경: 해당 API 하위와 작업 이력만 무효화한다.
- 회원 식별자 조회·음성 미리듣기 같은 읽기 명령은 조회 캐시를 무효화하지 않는다.
- 관리자 진입 권한은 변경 명령의 데이터 무효화 대상이 아니다. 화면 이동·포커스에서 최신 서버 승인과 모든 서버 API의 기존 권한 검증을 사용한다.
- 401/403은 화면을 차단하고 관리자 메모리 캐시와 진행 중 조회를 제거한다. 계정/세션 변경은 이전 세션의 관리자 캐시만 취소·제거한다. 다른 사용자 기능의 캐시는 건드리지 않는다.
- 캐시 재사용은 API 권한 검사를 대신하지 않는다. 삭제·편집·발송 명령에는 재시도나 결과 캐시를 추가하지 않는다.

## 첫 조회 개선

- 회원 기록 20개 COUNT의 소유 관계·집계 의미를 유지하며 UNION ALL 한 SQL 요청으로 합친다. DB 자체의 집계 작업 20개가 사라진다는 뜻은 아니다.
- 회원 목록의 등급은 payment 도메인 일괄 사실 조회 한 번으로 읽는다. TEST admin 우선순위·허용 사용자·현재 유효 결제 조건은 application 정책에서 유지한다.
- 분류별 기록/숫자 식별자 조회에서 필요하지 않은 등급·로그인 제공자 조회를 제거한다.
- 회원 records는 overview 완료를 기다리지 않고 병렬 요청한다. 양쪽 서버 API가 각자 현재 권한·회원 가시성을 검사한다.
- 삭제 패널은 현재 승인한 관리자 컨텍스트를 재사용하여 중복 /admin/me 요청을 피한다. 다음 화면의 권한 승인 요청을 캐시로 생략하지 않는다.

## 검증과 한계

실제 로컬 PostgreSQL과 Hibernate prepare-statement 통계로 20개 집계 SQL 1회, 페이지 등급 사실 SQL 1회를 확인했다. 기존 분류별 totalElements와 집계 결과도 대조했다. 유료 사실은 만료·미래 결제·취소를 제외하는지 검증했다. 브라우저에서 반복 콘텐츠 목록 이동의 데이터 요청 재사용과 별도 권한 재검사, 읽기 검색의 무효화 방지, overview 대기 없는 기록 요청을 확인한다.

운영 서버 지연 시간을 실측한 작업은 아니다. SQL 왕복과 불필요한 재요청을 줄인 결과이며, 네트워크·배포 환경에 따른 실제 체감 시간은 배포 후 확인해야 한다. 기존 결제 통합 검사 21개 실패는 작업 시작 main ae254ff에서도 동일하게 확인해 QA 문서에 분리했다. 운영 DB 수정이나 실제 회원 삭제는 실행하지 않았다.
