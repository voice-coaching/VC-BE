# CLOVA 상세 채점표와 조건부 프롬프트 v2

기준표 버전은 `clova-phone-rubric-v2`다. 같은 녹음의 전체 기대 음소와 각 음소의
CTC 정렬 후보·동결 검출 결과를 사용한다. 사람 평가로 보정된 발음 정확도나 공인
점수가 아닌 서비스 학습용 기준이다. 모델 가중치와 검출 임계값은 변경하지 않는다.

## 내부 채점표

| 항목 | 기대 표지 | 기본 배점 |
| --- | --- | ---: |
| 모음 | 현대 한글 모음 표지 21개 | 25 |
| 평음 파열음 | ㄱ ㄷ ㅂ | 10 |
| 경음 파열음 | ㄲ ㄸ ㅃ | 10 |
| 격음 파열음 | ㅋ ㅌ ㅍ | 10 |
| 마찰음 | ㅅ ㅆ ㅎ | 10 |
| 파찰음 | ㅈ ㅉ ㅊ | 10 |
| 비음 | ㄴ ㅁ ㅇ | 10 |
| 유음 | ㄹ | 5 |
| 기대 음소 대응 범위 | 전체 기대 음소의 정렬 커버리지 | 10 |

앞의 8항목은 기대 표지에 따른 서로 겹치지 않는 분류다. 실제 조음 위치나 받침
중화·연음의 옳고 그름을 글자에서 판정한 것이 아니다. 전체 40개 기대 표지는
정확히 한 분류에 속해야 하며 알 수 없는 표지는 임의 분류하지 않고 채점 실패 처리한다.

각 음소의 근거 단위는 CTC 일치/검출 미통과=4, 일치/검출 통과=2,
대치 후보/검출 미통과=3, 대치 후보/검출 통과=1, 삭제 후보=0이다.
검출 점수의 크기를 정확도 확률로 변환하지 않는다. coverage의 근거 단위는
`4 × 정렬 대응 음소 수`이며, 음소 분류별 점수와 별도로 전체 누락 후보를 반영한다.

| 근거 단위 / 가능한 최대 단위 | 단계 | 내부 설명 |
| --- | ---: | --- |
| 95% 이상 | 4 | 매우 안정적인 분석 근거 |
| 80% 이상~95% 미만 | 3 | 일부 재확인 |
| 60% 이상~80% 미만 | 2 | 반복 연습 |
| 40% 이상~60% 미만 | 1 | 재확인 지점 다수 |
| 40% 미만 | 0 | 안정적인 근거 부족 |

단계 경계 비교 전에 반올림하지 않는다. 해당 표지가 없으면 `level=null`로 평가에서
제외하고 만점이나 0점을 주지 않는다. 최종 점수는
`100 × Σ(적용 배점 × 단계) / (4 × Σ적용 배점)`를 소수점 첫째 자리 HALF_UP으로
반올림한다. 모음 4개 중 일치/미통과 3개·일치/통과 1개이면 모음 단계 3,
coverage 단계 4이며 다른 항목이 없을 때 총점은 82.1이다.

짧은 대본의 한 번 등장한 표지도 규칙대로 평가하지만 확신도를 높이지 않는다.
대본별 적용 항목이 달라 서로 다른 대본의 난이도가 보정된 점수는 아니다.
억양·속도·강세·쉼·입술·화자 특성에는 검증된 입력이 없어 가감점하지 않는다.
배점과 단계 경계는 제품 정책이며 사람 채점과의 일치도가 검증됐다는 뜻은 아니다.

## 채점 때만 읽는 파일 구조

- 정본 기준표: `configs/pronunciation_feedback/clova_pronunciation_rubric_v2.json`
- 채점 전용 프롬프트: `configs/pronunciation_feedback/prompts/scoring/pronunciation-v2.md`
- Git 심볼릭 링크: `configs/pronunciation_feedback/prompts/scoring/active.md` → `pronunciation-v2.md`
- 공통 시스템 참조: `clova_prompt_routing.SCORING_SYSTEM_REFERENCE`

일반 피드백은 `TASK_MODE=FEEDBACK`과 참조 경로만 전달한다. 채점표 파일은 읽지
않으며 프롬프트 본문도 전달하지 않는다. 채점 어댑터의 `score()`만 링크를 검증하고
대상 파일을 읽어 `TASK_MODE=SCORING` 시스템 지시와 채점표를 함께 전달한다.
CLOVA가 파일 시스템을 직접 탐색한다고 가정하지 않는다. 사용자 입력으로 모드를
선택할 수 없다. Windows의 `core.symlinks=false` 체크아웃은 지정된 대상명만 담은
포인터 파일로 처리하고, Linux Git 체크아웃과 운영 배포에서는 실제 심볼릭 링크다.
RunPod 재기동 overlay도 링크를 복원한다.

## 생성·저장·검증

CLOVA는 9개 `criterionId/level`과 `overallScore`를 출력한다. 워커와 백엔드는 같은
기준표를 사용해 분류별 개수 합, coverage와의 일치, 평가 제외, 단계 경계, 최종 합산을
검증한다. 근거·채점표·출력이 불일치하면 점수를 만들지 않고 실패 처리한다.
모델이 JSON 전체를 코드펜스 하나로 감싼 경우 그 외피만 제거한다. 설명에서 JSON을
추출하거나 잘못된 JSON·점수를 보정하지 않는다. 중복 키·추가 필드·기준표 불일치는 거절한다.
모델 입력에는 여섯 상태별 개수와 함께 정확한 근거 단위 합계·최대 단위·각 단계의
최소 정수 단위·합산 분모를 제공해 중간 산술 오류를 줄인다. 정답 단계나 정답 총점을
미리 넣지는 않는다. CLOVA가 기준표에서 선택한 단계와 출력한 총점의 검증은 유지한다.

HTTP 결과 v2는 유지하고 `scoringEvidence.rubricRevision`으로 기존 3항목 v1과
상세 v2를 구분한다. v2는 `criteria`, `rubricSha256`, `promptSha256`을 추가하고
기존 `alignmentScore/coverageScore/stabilityScore`는 보내지 않는다. 백엔드는 정본
기준표의 해시까지 확인한다. 프롬프트 해시는 실행 지시의 추적용이며 결과 내용과
함께 DB의 `clova_score_evidence`에 저장한다. 기존 결과는 소급 재채점하지 않는다.

백엔드의 호환 검증 코드를 먼저 배포한 뒤 워커·기준표·프롬프트를 배포한다.
공개 상세 API의 `overallScore`와 승급 제출 API는 같은 저장 점수를 사용한다.
