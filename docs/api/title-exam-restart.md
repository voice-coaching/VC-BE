# 승급시험 재개·새 시작

프런트는 시험 진입 시 시험과 연결된 세션·녹음 목록만 조회한다. 기존 녹음 또는 분석이 있으면 사용자가 재개/새 시작을 선택할 때까지 분석 접수·재시도·채점·취소를 호출하지 않는다. 재개는 기존 조회·분석 API를 사용하며, 아직 분석하지 않은 저장 녹음은 별도의 분석 버튼으로 접수한다.

`POST /api/users/me/title-exams/{examId}/restart`

요청 본문: `{"previousTrainingSessionId": 123}`. 양의 정수이며 필수다. 응답은 기존 `TitleExamResponseDto`와 같은 API envelope로, 새 `trainingSessionId`와 현재 시험 정책을 반환한다.

- 사용자와 시험 소유 관계를 확인하고 사용자 → 이전 학습 세션 순으로 잠근다. 탈퇴·정지 사용자는 거부하고, 채점된 시험은 `TITLE_EXAM_ALREADY_GRADED`로 거부한다. 채점 완료 후 새 시험 응시는 기존 시험 생성 API의 자격·정책을 따른다.
- 요청의 이전 세션 ID가 현재 연결과 다르면 현재 시험을 반환한다. 응답 유실 후 같은 요청을 다시 보내거나 다른 탭이 재시작해도 새 세션을 다시 취소·생성하지 않는다.
- 진행 중인 이전 세션은 기존 취소 서비스를 사용한다. 분석 취소 outbox, 녹음 정리 예약, 동의 철회와 upload intent 만료를 유지한다. 이미 COMPLETED/FAILED/CANCELED인 세션은 상태를 되돌리지 않는다.
- 같은 미채점 시험에 새 PRONUNCIATION 세션을 연결한다. 시험 콘텐츠·목표 칭호·고정 합격점은 유지한다. 완료된 이전 학습 기록은 보존하며, 이전 세션의 점수는 새 연결의 채점에 사용할 수 없다.
- 새 세션 생성이나 저장이 실패하면 같은 트랜잭션의 이전 세션 취소·시험 재연결도 롤백한다. 재시작 자체는 음성 업로드·분석 접수·점수 생성·승급을 실행하지 않는다.

DB migration과 AI 계약 변경은 없다. Backend API를 먼저 배포해야 프런트의 새 시작이 동작한다. 컴파일·정적 확인은 실제 녹음/추론·품질 QA나 운영 배포 근거와 구분한다.
