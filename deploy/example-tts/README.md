# Independent example TTS

> Update 2026-09-19 16:46 KST: authorized AWS token storage, nginx route and worker activation are complete. Five examples are GENERATED; public listening approval remains pending. See [current operations](../../docs/architecture/example-tts-operations-20260919.md) for actual environment names and rollback. Earlier pending steps below are historical.

This service generates Korean example audio separately from the analysis API and scorer.
The public example-audio endpoint reads generated bytes only after two distinct reviewer
identities approve the exact SHA-256. Generation alone never creates review approvals.

## Runtime

- Python 3.10.18 in `/opt/voice-coaching-tts/venv`; pinned dependencies in `requirements.lock`.
- Melo/model/tokenizer versions are recorded in `runtime-manifest.json`.
- Persistent assets/code: `/workspace/voice-coaching-tts`; ephemeral status/logs: `/run/voice-coaching-tts`.
- `manager.py` owns its own lock and supervises only TTS. It does not restart the existing AI supervisor.
- API listens on loopback 8082, one model child, GPU concurrency one, one waiting slot, two-second queue deadline.
- Model initialization includes a Korean warm-up. Runtime downloads are disabled. Korean MeCab and UniDic must be installed before readiness.
- The dedicated token is supplied through `TTS_TOKEN_FILE`, never committed. Default manager path is `/workspace/voice-coaching-tts/secrets/token`.
- Start explicitly: `/opt/voice-coaching-tts/venv/bin/python /workspace/voice-coaching-tts/service/manager.py`.
- Pod recreation requires restoring the dedicated environment and invoking the manager from the pod startup configuration. Startup-hook registration has not yet been verified; a persistent model directory alone is not reboot recovery.

## AWS configuration

`EXAMPLE_TTS_PROVIDER=runpod` selects approved-cache-only public audio. With no new provider
setting, the existing Google enabled/disabled behavior remains unchanged.

`EXAMPLE_TTS_WORKER_ENABLED=true` independently enables background generation. Also configure
`EXAMPLE_TTS_BASE_URL` (HTTPS), `EXAMPLE_TTS_API_TOKEN`, `EXAMPLE_TTS_REVISION`,
`EXAMPLE_TTS_FINGERPRINT`, `EXAMPLE_TTS_DECODER`, and `EXAMPLE_TTS_PROBE`.
The deployed EC2 decoder is under `/opt/voice-media/ffmpeg/`; resolve its actual pinned binary
before setting these paths. No additional global ffmpeg installation is required.

The RunPod HTTP proxy does not expose 8082. The prepared transport is a dedicated EC2 systemd
SSH tunnel (loopback 18082 → RunPod loopback 8082), using an EC2-generated key restricted on
RunPod to that destination and denied command execution. Known-host verification is mandatory.
Only an exact nginx `/v1/tts/synthesize` location is to route into the tunnel; all existing analysis
locations stay unchanged. Token transfer and nginx activation are pending explicit approval.

## Database workflow

V30 adds a transactional INSERT outbox, immutable model profiles, unique example/profile jobs,
and byte-bound reviewer decisions. A dedicated executor reconciles missing jobs every five seconds,
claims using `FOR UPDATE SKIP LOCKED`, and performs network and decoding outside transactions.
Only a current, unexpired lease can publish bytes. The 90-second lease exceeds the adapter's
30-second deadline; this implementation uses lease expiry recovery, not a heartbeat thread.

Temporary failures retry at most five attempts with 10/30/120/600-second backoff and bounded jitter.
Internal authentication/revision errors halt the worker until corrected and restarted. Unapproved
audio, cache misses and digest corruption return `TTS_UNAVAILABLE`; GET does not synthesize.
The default deployment leaves the worker disabled. A new profile revision schedules new jobs
without overwriting prior audio. Existing examples are backfilled by the migration/reconciler.

`publish-course-301.sql` contains the five original FE final-consonant sentences mapped to the
existing published course 301, step 303, education revision 3. It is an operator-run transaction,
not an automatic migration. It refuses to overwrite an existing example set.

## Validation and rollout

- Test migrations against the disposable PostgreSQL loopback cluster, never production RDS.
- Deploy additive schema and backend with worker disabled, verify application health, then configure
  the authenticated transport and enable generation. Verify GENERATED rows, digest, duration and attempts.
- Export the actual candidate MP3s for listening; record each reviewer's decision against the stored
  digest. Do not infer approval from HTTP 200, STT or successful decoding.
- Switch public provider only after approved cache coverage is verified.
- Roll back by disabling the worker and restoring the prior provider/JAR. Preserve jobs, approved bytes
  and additive tables. Stop only the TTS manager/tunnel when decommissioning; never restart CLOVA.

Observed on 2026-09-19: a roughly 4.4-second Korean sentence took 4.656 seconds on first use and
0.309–0.461 seconds for three subsequent GPU syntheses (before HTTP/MP3 overhead). Local TTS API
benchmark: concurrency one, 100/100 success, p95 706 ms; concurrency two, 100/100 success, p95 1245 ms.
An eager concurrency-four burst returned 98/100 HTTP 429s under the intentionally small queue.
These are TTS-only measurements, not AWS/browser latency or proof of noninterference under analysis load.
